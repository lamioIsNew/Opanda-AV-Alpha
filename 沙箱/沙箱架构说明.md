# 沙箱架构说明（截至本轮）

## 一、结论先行

把"沙箱"拆成**三层**，按**样本类型**分流，不再让所有样本都走同一条重管线：

| 层 | 工具 | 适用样本 | 实测耗时 | 隔离强度 | 现状 |
|---|---|---|---|---|---|
| L0 静态快筛 | `scan.exe` | 全部 | 毫秒/样本 | 不执行（零风险） | 已完成 |
| L1 **脚本虚拟沙盒** | `unbox_js.py` + `js_vm.exe` | `.js .jse .vbs .vbe .wsf` 等脚本 | **31–78 ms** | 不给任何真实宿主对象 | **本轮新建并实测通过** |
| L2 原生行为追踪 | `guest_agent.exe`（HVM） | PE 二进制 | 秒级（检查点回滚） | Hyper-V 虚拟机 | 采集器已完成，编排待建 |
| L3 深度隔离 | `auto_analyze.ps1`（WSB） | 高危/交互型/需要真环境的 | 分钟级 | Windows Sandbox，用完即弃 | 已有，保留不动 |

**WSB 和 HVM 都保留**：WSB 做"深度隔离的一次性取证"，HVM 做"可复用、秒级回滚的原生行为采集"。两者都不负责脚本类样本——那是 L1 的活。

## 二、为什么要分层（你给的那份 PDF 是决定性的）

火绒《"脚本行为沙盒"简介》里写得很清楚：他们的**脚本沙盒不是虚拟机**，而是在引擎内部实现了一套
**虚拟 Windows 内核 + 虚拟运行时**，在里面跑一个仿真的 `WScript.exe`，把"脚本问题转化成 PE 问题"，
再复用已有的行为检测逻辑。因为它**根本不引导操作系统**，所以 5 秒说得通。

我原先那套"Hyper-V 预热 VM 分析脚本"是**用错工具**：
WSB/HVM 的几十秒全部花在"引导一个 Windows"上，而脚本样本根本不需要 Windows——
它需要的是**一个能骗过它的脚本运行时**。

本轮我们就照这条路做了 L1（见《脚本虚拟沙盒说明.md》），实测：
- 822 KB 的变形 `.js`：静态剥壳 + 受控执行 **62 ms** 拿到真实代码
- 还原出来的代码再放进虚拟执行 **31 ms**，直接抓到它的网络动作

## 三、三层的分工逻辑（判定流）

```
样本进来
  │
  ├─ L0 静态：scan.exe 出「高危」
  │     └─ 已经是高危 → 直接定案（不动沙箱，省时间）
  │
  ├─ L0 出「仅疑似/漏报」且是脚本类
  │     └─ L1 脚本虚拟沙盒：剥壳 → 还原 → 虚拟执行
  │           ├─ 拿到 URL/落地名/Run 命令行 → 升级为「高危 + 行为描述」
  │           └─ 还原失败 → 落回 L3 WSB（极少数）
  │
  ├─ L0 出「仅疑似/漏报」且是 PE（.exe/.dll/.sys）
  │     └─ L2 HVM：检查点回滚 + 原生 ETW 采集（进程/文件/注册表/TCP/DNS）
  │           └─ 仍需交互/观察界面 → L3 WSB
  │
  └─ 已知高风险、要"看它到底干了什么" → L3 WSB（一次性）
```

关键点：**越便宜的层越先走**，只有前面的层给不出结论才升级。

## 四、8 GB 内存下的取舍

- WSB：**用完即弃**，同一时刻只允许 1 个实例，避免内存叠加。
- HVM：**只预热 1 台**，靠 `Restore-VMCheckpoint` 回滚，不反复开关机（开机一次约 20–40 秒，回滚只需秒级）。
- L1：纯进程内执行，内存占用几 MB，可并发。
- 三层不会同时满负荷：L1 几乎瞬间结束，L2/L3 按需触发。

## 五、与现有 WSB 管线的关系

现有 `行为沙箱\`（`guest_monitor.ps1` / `auto_analyze.ps1` / 行为沙箱说明.md）**一行不改**，
继续作为 L3。本轮新增的 L1 是**前置分流**，不替代它：
先让便宜的 L1 把"其实是脚本下载器"的样本筛掉，WSB 那几分钟的预算留给真正需要它的样本。

## 六、建议的下一步（按性价比排序）

1. **把 L1 接进主流程**：`scan.exe` 对脚本类样本判「疑似/漏报」时，自动调用
   `unbox_js.py` → 命中"URL + Run + 落地路径"三件套即升级「高危」，
   并把还原出来的行为写进 `检测名/细节`（这一步的收益最大，直接吃掉当前 74 个"仅疑似"里的一大块）。
2. **L1 扩展到 VBScript**：同一套宿主换 `VBScript.dll`（CLSID `{B54F3741-5B07-11CF-A4B0-00AA004A55E8}`）即可，
   样本集里有 24 个 `.vbs` + 24 个 `.vbe`。
3. **L2 编排**：`准备HVM分析机.ps1`（建 VM + 装 PSDirect + 拍检查点）+ `hvm_analyze.ps1`（回滚 → 投样 → 采集 → 回传 → 复用现有评分）。
4. **HTA / PS1**：HTA 属 HTML+脚本，需浏览器级环境，建议直接交给 L3；PS1 仍走现有"脚本块审计"。
