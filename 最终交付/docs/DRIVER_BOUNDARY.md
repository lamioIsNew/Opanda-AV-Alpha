# 驱动与内核执行端：边界说明

## 1. 本包为什么没有驱动二进制

本里程碑的交付范围是：

- 静态扫描 DLL；
- 外部特征库；
- WD 风格 GUI。

驱动执行端（强杀/强删/自保护）**没有包含在本包中**，原因：

1. 内核驱动需要 WHQL/attestation 签名；用户明确由自己负责签名；
2. minifilter 需要分配并确认 altitude；
3. 未签名驱动在启用驱动签名强制的机器上无法加载，强制加载可能触发系统策略或破坏系统；
4. 驱动必须在独立测试机 + 测试签名 + 可回滚快照下验证，不能直接对生产机/分析机安装。

GUI 的“驱动与内核”页会显示“未安装”，不会尝试加载未签名驱动。

## 2. 未来驱动的能力边界

如果后续实现，驱动只做**执行端**，不做判定：

- 强制结束进程：普通进程可结束；PPL/受保护进程受系统限制；
- 强制删除文件：被映射/占用的文件可能只能重启后删除；
- 自保护：保护服务进程、驱动自身与关键文件；挡不住内核级攻击；
- 控制设备：只允许 SYSTEM 打开；不提供任意内核读写、任意地址映射、任意进程内存读写；
- 维护模式：提供明确的服务停止、驱动卸载与回滚路径；
- 判定仍在用户态：驱动不参与“是不是恶意”的结论。

## 3. 建议的落地顺序

1. 先做用户态服务：文件事件订阅、扫描队列、隔离、日志；
2. 用 minifilter 做文件保护/拦截，先只观察不阻断；
3. 独立测试机加载测试签名驱动，验证蓝屏/死锁/卸载；
4. 再接入强杀/强删/自保护；
5. 最后做 WHQL/attestation 与正式分发。

## 4. 安全约束

- 不暴露任意内核读写；
- 设备 ACL 只允许 SYSTEM；
- 所有 IOCTL 做长度/版本/权限校验；
- 维护模式可卸载；
- 驱动崩溃不能导致用户数据损坏；
- 任何执行动作都应由用户态明确请求，并记录审计日志。
