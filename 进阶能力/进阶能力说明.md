## 一、风险名称细颗粒度（已完成）

### 现状
`scan.exe` 输出的检测名从早期的粗颗粒度（`Trojan.Win32.Generic` 之类）细化到了
**家族级**，来源分三层：

| 层级 | 机制 | 举例 |
| --- | --- | --- |
| 特征码 | `signature_scan.c` 的 `sig_db[]`，命中即给家族名 | `Backdoor.Win32.NjRAT`、`Ransom.Win32.KeyPass`、`Trojan.Win32.BrowserFleet` |
| 行为规则 | `script_scan.c` 按行为类别（勒索/下载/混淆/持久化/COM）拼名 | `Ransom.Script.Generic`、`Trojan.Script.Downloader`、`Trojan.Script.Dropper` |
| 模型 | ML 分数达标但无家族特征时给"疑似家族" | `Suspicious.ML.<分数段>` |

### 本轮新增的家族级特征（约 30 条）
NjRAT / KeyPass / WannaCry / LockBit / Conti / REvil / GandCrab / StopDjvu /
AsyncRAT / Quasar / Remcos / NanoCore / DarkComet / Gh0st / AgentTesla /
Formbook / LokiBot / Mimikatz / Meterpreter / CobaltStrike / XMRig 矿工 等。

### 关键工程约束（容易踩的坑）
1. **顺序敏感**：`sig_db[]` 是 **first-match-wins**，组合特征/精确特征必须排在
   宽泛的单关键词**前面**（例如 `cmd.exe /c powershell -enc` 必须排在 `cmd.exe` 之前）。
2. **大小写敏感**：匹配用的是逐字节 `memcmp`，**不是**忽略大小写。特征串必须照抄
   样本里真实的大小写（这一点直接导致过误判：`emotet` 曾命中
   `CreateRemo**te**Thre**ad**` 里的巧合子串，已废弃）。
3. **可验证**：每条新特征都做了定点验证（正样本必须报毒、无害样本不许误报）+
   全样本集 A/B 回归（改判列表逐条人工过目）。

## 二、沙箱自动化集成（已完成）

### 已实现的"全自动一条链"
```
待跑样本  ──► auto_analyze.ps1  ──► 启动 Windows Sandbox（断网/联网可选）
                     │                        │
                     │                        ├─ 样本落盘、拉起、观察进程树/注册表/文件/网络
                     │                        └─ guest_monitor.ps1 每秒采样，写 report.json
                     ▼
            静态扫描（scan.exe）+ 动态行为评分 ──► 汇总表 + Markdown 明细
```
- **一条命令**：`.\auto_analyze.ps1 -Target <样本或目录> -All -Network -Top N`
- **自动算分**：静态分 + 行为分（持久化、提权、外联、进程注入、勒索痕迹…）加权
- **结果三份**：控制台汇总表、`*.md` 明细、`report.json`（机器可读）
- **网络归因**：见第三节说明（按样本进程树逐 PID 归因，系统基线流量不会混进来）

### 批量能力
`-Top N` 支持一次喂一个目录，逐个开沙箱跑完自动关机清场；跑完自动
`Close-AllSandboxes` 强杀残留沙箱进程（宿主侧）。

### 已知局限
| 局限 | 影响 | 规避 |
| --- | --- | --- |
| 沙箱默认**断网** | 网络依赖型样本无法观测外联 | 加 `-Network` |
| 采样是"每秒定点" | 极短命进程/一次性连接可能漏 | 关键样本多跑几次 |
| 沙箱内是精简系统 | 依赖特定软件（如 QQ/游戏）的样本行为不全 | 需要在真机/全量虚拟机复核 |
| 单样本约 1.5–2 分钟 | 大批量耗时长 | 缓存复用（同哈希不重跑） |

## 三、基础主动防御（已完成）

### 1) 目录实时监控 `folder_guard`（用户态，第一版）
位置：`..\主动防御\`（`folder_guard.exe` + `主动防御.cmd` + `folder_guard.c`）

- 用 `ReadDirectoryChangesW` 监控**下载 / 桌面**（可 `--dir` 指定，可 `--recursive`）
- 新落地 `.exe/.dll/.sys/.ps1/.cmd/.vbs/.js/.hta` 等 → 等文件写完 → 调 `scan.exe` 静态扫描
- 命中 `[HIGH RISK` → 控制台告警；加 `--lock` 则用 `SetFileAttributesW` **置为只读**（落地即拦截）
- **实测**：投放"命中特征码的无害测试体"→ 告警 + 自动置只读；投放干净脚本 → 放行不动作

局限（必须说清）：
- 这是**用户态、事后、按文件落地**的防护，不是内核拦截；
- 只覆盖静态能判的部分；免杀样本落地时判不出来，需要行为沙箱兜底；
- `--lock` 只是置只读，用户可手动改回（不是杀进程/隔离区）。

### 2) 启动项体检 `scan_startup.ps1`（已有）
枚举 Run 键 / 启动文件夹 / 计划任务 / 服务，逐个送 `scan.exe` 扫描，
用于排查"开机自启型"持久化。

## 四、脚本块审计（本轮新增，AMSI 的用户态等效替代）

位置：`..\进阶能力\脚本块审计\`（`脚本块审计.ps1` + `脚本块审计.cmd`）

### 它解决什么问题
真 AMSI 是在**脚本执行前**把内容交给杀软；但真 AMSI 需要注册 in-proc COM 组件。
本项目用 **PowerShell 脚本块日志（Event ID 4104）** 做"执行后审计"，把
每一个 `-enc` / `IEX` / `DownloadString` 脚本块重新走一遍 `scan.exe`：

```
PowerShell 引擎 ──(4104 事件, 含完整脚本块文本)──► 脚本块审计.ps1 ──► scan.exe ──► 告警
```

### 用法
```powershell
.\脚本块审计.ps1                  # 审计最近 1 小时
.\脚本块审计.ps1 -Minutes 360     # 回看 6 小时
.\脚本块审计.ps1 -Follow          # 每 30 秒盯新增（适合挂着）
.\脚本块审计.ps1 -EnableLogging   # 打开脚本块日志（需管理员，一次性）
```
已看过的脚本块落盘去重，不会重复告警。

### 与真 AMSI 的取舍
| | 真 AMSI 提供程序 | 本方案（4104 审计） |
| --- | --- | --- |
| 时机 | **执行前拦截** | 执行后审计 |
| 部署成本 | COM 注册（HKLM）+ 数字签名 | 零注册表、零签名 |
| 覆盖面 | 所有 AMSI 宿主（PS/VBS/JS/.NET…） | 仅 PowerShell（可另接 4688/VBScript 事件） |
| 稳定性风险 | 组件崩溃会拖累宿主进程 | 完全隔离，崩了只影响自己 |

**结论**：先上本方案（今天就能用）；等有签名证书再上真 AMSI 做拦截。

## 五、真 AMSI 提供程序（给出设计与源码骨架，未编译、未注册）

源码骨架：`..\进阶能力\AMSI提供程序\amsi_provider.c`

### 原理（Windows 官方机制）
1. 实现 COM 接口 `IAntimalwareProvider`（`Scan(IAmsiStream*, AMSI_RESULT*)` +
   `CloseSession` + `DisplayName`），接口与 IID 由 Windows SDK 的 `amsi.h` 提供；
2. 编译成 **in-proc COM 服务 DLL**，导出 `DllGetClassObject` / `DllCanUnloadNow`；
3. 注册到 `HKLM\SOFTWARE\Microsoft\AMSI\Providers\{<你的CLSID>}`；
4. AMSI 宿主进程（PowerShell、VBScript、Office VBA…）加载后，
   引擎把待执行内容 `Write` 进 `IAmsiStream`，调用你的 `Scan`，你返回
   `AMSI_RESULT_DETECTED` 即**当场阻断执行**。

### 为什么本轮"不落地安装"
1. **必须数字签名**：没签名/没被信任的 provider DLL 在宿主进程里加载会被拒绝或
   直接被 AMSI 忽略；自签名证书只在你自己机器上凑合，换机即失效；
2. **写 HKLM + 注入所有宿主的风险**：provider 里任何崩溃/死锁都会**拖死 PowerShell、
   Office、VBScript 宿主**，属于"装上去容易、摘下来麻烦"的组件，不适合在
   没有签名与回滚预案的情况下往你机器上塞；
3. 因此：**交付源码 + 注册/注销脚本 + 设计说明，由你自己决定何时启用**。
   注册脚本会先打印将要写入的键值并要求二次确认。

### 落地时的两个关键工程点
- `Scan` 里**不要**调用外部进程（`scan.exe`）：AMSI 是同步热路径，起进程会慢到不可用，
  必须把特征匹配/规则判断**编译进 DLL**（可直接复用本项目 `signature_scan.c`
  与 `script_scan.c` 的纯函数部分）；
- 必须处理 `IAmsiStream::GetAttribute(AMSI_ATTRIBUTE_CONTENT_ADDRESS/SIZE)` 的
  **分块读取**，并给 `Scan` 加硬超时（比如 5ms 内返回 `AMSI_RESULT_NOT_DETECTED`），
  否则会卡住宿主。

## 六、PPL（受保护进程轻量级）——结论：**做不到，跳过**

原因不在技术难度，而在**准入**：

- PPL（`PROTECTED_PROCESS_LIGHT`）是内核强制的保护等级，进程要被内核认作 PPL，
  必须满足：**驱动由微软签名（ELAM 级别）+ 进程镜像带特定 EKU 的证书签名
  + 内核侧配合注册**；
- 这条链子的第一环（ELAM 驱动签名）只有通过微软的 **WHQL/EV 代码签名 + 微软
  另签**才能拿到，个人开发者与无 ISV 主体拿不到；
- 换句话说：**没有微软给的那张证书，代码写得再对，内核也不认**。

### 替代方案（同样的目的：让"防护进程"不易被杀）
1. **Windows 服务 + 服务恢复策略**：把防护组件做成 `LocalSystem` 服务，配置
   "失败自动重启"（`sc failure`），被结束进程后由 SCM 拉起来 —— 用户态条件下
   性价比最高；
2. **双进程互保**：主/守进程互相监视，一方被杀另一方立刻重启它（仍可被一起杀，
   但成本提高）；
3. **驱动级保护**：只有拿到 EV 证书 + 微软签名的内核驱动才行（即上面的门槛）。

**建议**：现阶段用"服务 + 恢复策略"，把力气留给检出率。

## 七、用户态 hook —— 结论：**不建议做，跳过**

### 常见做法与为什么都不合适
| 做法 | 问题 |
| --- | --- |
| IAT/EAT 改写（hook `kernel32!CreateFileW` 等） | 只能覆盖"按名字走 IAT"的调用，直接 `GetProcAddress` / syscall 绕过；且要对每个进程注入，自身极易被杀软当恶意行为打掉 |
| Inline hook（改函数头 5 字节） | 需要改目标进程内存（`WriteProcessMemory` + `SetThreadContext`），**行为特征和恶意软件注入完全一致**，会被本机杀软和 EDR 直接拦 |
| `AppInit_DLLs` | Win8 起要求 DLL 被签名（Secure Boot 下更强），基本已废 |
| `SetWindowsHookEx` | 只能注入有消息循环的 GUI 线程，覆盖面极窄 |

### 更合适的替代：**ETW 事件驱动**
内核已经在采集你要的信息，直接订阅，不用注入、不用驱动：
- `Microsoft-Windows-Kernel-Process`：进程创建/退出；
- NT Kernel Logger（FileIo / Registry）：文件与注册表写入；
- `Microsoft-Windows-PowerShell/Operational`：脚本块（见第四节，已落地）；
- 安全审计 4688/4104/5156 等。
代价是"看到的是事件，不是调用栈"，但对"发现落地→执行→持久化"这条链足够。

**建议**：主动防御走"ETW 订阅 + 定时静态扫描 + folder_guard"三条腿，
用户态 hook 这条线不做。
